## Шпаргалка по новым API (Читать обязательно!)

Для выполнения заданий вам понадобятся несколько встроенных возможностей браузера. Мы не изучали их на лекции подробно, поэтому вот готовые паттерны, которые нужно использовать.

### 1. Сохранение данных в браузере (`localStorage`)
`localStorage` хранит данные между перезагрузками страницы, но **принимает и возвращает только строки**.
`setItem(key, value)`
Метод, который записывает пару в хранилище.

```typescript
localStorage.setItem("catalog", "какая-то строка");
//                      ↑ ключ       ↑ значение (обязательно string)
```
Первый аргумент — имя ключа ("catalog").

Второй — значение. Если передать не строку, браузер сам приведёт её к строке (setItem("x", 42) сохранит "42"). Но с объектом так делать нельзя — получите бесполезное "[object Object]".

`JSON.stringify(value)`
Функция, которая превращает JS-значение в строку в формате JSON.

```typescript
// Сохранение: превращаем объект/массив в строку
const myData = { name: "Аня", age: 20 };
localStorage.setItem("catalog", JSON.stringify(myData));

// Чтение: достаем строку и превращаем обратно в объект
const raw = localStorage.getItem("catalog"); // вернет строку или null
if (raw) {
  const parsedData = JSON.parse(raw); // теперь это снова объект
  console.log(parsedData.name); // "Аня"
}
```
Что делает `if (raw)`

В JavaScript `if (...)` приводит значение к boolean. Для строк работает так:

| Значение `raw`            | `Boolean(raw)` | Ветка выполнится? |
|---------------------------|----------------|-------------------|
| `null`                    | `false`        | ❌ нет            |
| `undefined`               | `false`        | ❌ нет            |
| `""` (пустая строка)      | `false`        | ❌ нет            |
| `"{\"name\":\"Аня\"}"`    | `true`         | ✅ да             |
| `"0"` (строка с нулём)    | `true`         | ✅ да             |

То есть `if (raw)` — это **неявная проверка «не null и не пустая»** сразу.

### 2. Работа с выпадающим списком (`<select>`)
В JavaScript он работает точно так же, как `<input>`! У него есть свойство `.value`.
```html
<!-- В index.html -->
<select id="sortBy">
  <option value="year">По году (новые)</option>
  <option value="rating">По рейтингу</option>
</select>
```
```typescript
// В main.ts
const sortBySelect = document.querySelector('#sortBy') as HTMLSelectElement;
console.log(sortBySelect.value); // вернет "year" или "rating"
```

### 3. Анимация появления (CSS классы)
В файле `styles.css` уже добавлен класс `.fade-in`. Чтобы элемент появился плавно, используйте `classList.add` (Слайд 16 Лекции 3):
```typescript
const card = document.createElement('div');
card.classList.add('book-card', 'fade-in'); 
```

### 4. Сортировка массива объектов (Иммутабельно!)
Метод `.sort()` меняет исходный массив. Чтобы не нарушать принцип иммутабельности, сначала сделайте копию массива через `[...]` (spread-оператор).
```typescript
// Сортировка по году (от новых к старым). ?? 0 защищает от undefined.
const sortedByYear = [...books].sort((a, b) => (b.year ?? 0) - (a.year ?? 0));

// Сортировка по рейтингу (от высокого к низкому)
const sortedByRating = [...books].sort((a, b) => (b.rating ?? 0) - (a.rating ?? 0));
```

## Публикация на GitHub Pages

1. Убедитесь, что в `vite.config.ts` указано правильное имя репозитория:
   ```typescript
   export default defineConfig({
     base: '/practice-2-2/', // замените на имя вашего репозитория
   })
   ```
   Зачем: Vite по умолчанию считает, что сайт лежит в корне домена (`/`), а GitHub Pages отдаёт его из папки `/имя-репозитория/`. Без правильного `base` сайт откроется, но стили и скрипты не загрузятся.
   Если вы сделали форк — имя репозитория совпадает с `base`, менять ничего не нужно. Если создали репозиторий с другим именем — подставьте его между слешами.

2. Установите пакет позволяющий размещать статические сайты прямо из репозитория на GitHub
   ```bash
   npm install -D gh-pages
   ``` 
   
3. Соберите проект:
   ```bash
   npm run build
   ```
   Зачем: GitHub Pages не умеет запускать `npm run dev` и не читает TypeScript — ему нужны готовые файлы. Команда компилирует TS и упаковывает всё в папку `dist`. Это и есть будущий сайт.
   
4. Опубликуйте:
   ```bash
   npx gh-pages -d dist
   ```

   Зачем: команда создаёт в вашем репозитории отдельную ветку `gh-pages` и загружает туда содержимое `dist`. Ветка `main` остаётся для исходного кода, `gh-pages` — только для собранного сайта. Пакет `gh-pages` уже добавлен в `package.json`, отдельно устанавливать его не нужно.

5. Включите GitHub Pages (делается один раз):
   **Settings → Pages → Source: Deploy from a branch → Branch: `gh-pages`, папка `/ (root)` → Save.**
   
6. Откройте ссылку `https://ваш-ник.github.io/practice-2-2/` — сайт станет доступен через 1–2 минуты.
